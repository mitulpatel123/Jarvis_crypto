═══════════════════════════════════════════════════════════════════════════════
DATABASE TRUNCATION COMMANDS (DETAILED)
═══════════════════════════════════════════════════════════════════════════════

Method 1: TRUNCATE (RECOMMENDED - Fast & Clean)
────────────────────────────────────────────────────────────────────────────────
docker exec crypto_timescaledb psql -U postgres -d crypto_data \
  -c "TRUNCATE TABLE feature_store;"

• Instantly removes all rows
• Preserves table schema
• Resets auto-increment sequences
• Most efficient method

Method 2: DELETE (Alternative - Slower)
────────────────────────────────────────────────────────────────────────────────
docker exec crypto_timescaledb psql -U postgres -d crypto_data \
  -c "DELETE FROM feature_store;"

• Removes rows one by one (slower)
• Keeps transaction log
• Use if you need rollback capability

Method 3: DROP & RECREATE (Nuclear Option)
────────────────────────────────────────────────────────────────────────────────
docker exec crypto_timescaledb psql -U postgres -d crypto_data \
  -c "DROP TABLE feature_store CASCADE;"

# Then restart data factory - it will recreate the table
tmux new -d -s crypto_factory 'cd ~/Crypto && python3 run_data_factory.py > factory.log 2>&1'

• Only use if schema changed
• Most destructive - removes everything including structure
